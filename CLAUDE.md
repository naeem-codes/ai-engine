# CLAUDE.md — ai-engine

## What This Project Is

A Python FastAPI service that handles all AI/LLM logic for the SolidWorks CAD automation tool. It receives model data + a user instruction from the .NET `CAD-Automation` app, calls Claude or OpenAI, and returns a flat list of `(dimension_name, new_value_meters)` pairs.

No SolidWorks dependency — runs independently on any OS.

**Companion app:** `d:\Projects\collectiveXP\CAD-Automation` — the .NET WinForms app that connects to SolidWorks and calls this service.

## API

### `GET /health`
Health check. Returns `{"status": "ok"}`.

### `POST /interpret`
Main endpoint. Receives model context + instruction, returns dimension changes.

**Request fields:**
- `instruction` — user's natural language text
- `dimensions` — list of `{name, value_meters}` for all model dimensions
- `assembly_context` — full text dump from SolidWorks (includes COMPONENT RELATIONSHIP MAP)
- `model_path` — path to `.SLDASM`/`.SLDPRT` (used to load rules file)
- `dim_axis_labels` — `{"DimName": "W"|"H"|"?"}` pre-classified by the .NET app
- `master_width_dim`, `master_height_dim` — reference dimensions for proportional scaling

---

## Processing Logic — Three Cases

`interpret.py` applies these in priority order:

### Case 1: Rules-based
- Triggered when `rules/<ModelStem>.rules.json` exists
- LLM identifies trigger keyword + value from instruction
- `rules.validate()` checks min/max size limits
- `rules.expand()` multiplies trigger value by each dimension's ratio
- Low token usage (max_tokens=256), fast and deterministic

### Case 2: Classification (CONNECTED / OVERALL / SINGLE scope)
- Triggered when no rules file but `dim_axis_labels` is populated
- LLM receives full `assembly_context` (including COMPONENT RELATIONSHIP MAP) + dimension list
- Three scopes:
  - **OVERALL** — no component named → scale all [W]/[H] dims proportionally
  - **CONNECTED** — component named without ONLY/JUST → include named component + all mated components from COMPONENT RELATIONSHIP MAP
  - **SINGLE** — user says ONLY/JUST → change only that component's dims
- Engine calculates ratio-based values using master dim as reference
- Higher token usage (max_tokens=2048)

### Case 3: Error fallback
- No rules, no `dim_axis_labels` → returns error asking user to Refresh first

---

## The CONNECTED Scope — Key Design Decision

The most important scope for the KELLY mirror assembly. When a user says "increase the mirror width", they implicitly expect the chassis, LED strips, and other mated components to resize too.

The `assembly_context` now contains a **COMPONENT RELATIONSHIP MAP** section generated by the .NET app that shows which components are mated to which (e.g. `9535-CHASSIS ↔ 1021-MIRROR-KELLY [Coincident×4]`).

The `classification_prompt` instructs the LLM: when a component is named, look up that component in the map and include all directly-mated components' dimensions in the response.

## Prompt Templates (`prompts.py`)

### `rules_prompt(triggers)`
Short prompt for Case 1. Returns trigger keyword + value or direct changes.

### `classification_prompt(assembly_context, dim_list, master_width_dim, master_height_dim)`
Long prompt for Case 2. Embeds the full assembly context (which includes the COMPONENT RELATIONSHIP MAP). Defines OVERALL, CONNECTED, and SINGLE scope rules and expected JSON formats.

## LLM Configuration

| Variable | Description | Default |
|---|---|---|
| `ANTHROPIC_API_KEY` | Anthropic API key | required if using Claude |
| `OPENAI_API_KEY` | OpenAI API key | required if using OpenAI |
| `DEFAULT_PROVIDER` | `claude` or `openai` | `claude` |
| `PORT` | Server port | `8000` |

Edit `.env` to switch providers. Currently configured as `DEFAULT_PROVIDER=openai` (GPT-5.1).

LLM clients are in `llm.py`. `call_llm()` routes to Claude or OpenAI based on `DEFAULT_PROVIDER`.

## Rules Files

Create `rules/<ModelName>.rules.json` where `<ModelName>` matches the SolidWorks file stem (e.g. `KELLY-24.00X48.00-LED.SLDASM` → `KELLY-24.00X48.00-LED.rules.json`):

```json
{
  "model": "KELLY-24.00X48.00-LED",
  "limits": {
    "min_width_mm": 300,
    "max_width_mm": 1500,
    "min_height_mm": 400,
    "max_height_mm": 2000
  },
  "rules": [
    {
      "trigger": "width",
      "dimensions": [
        { "name": "WIDTH@Chassis [9535-CHASSIS]", "ratio": 1.0 },
        { "name": "WIDTH@Mirror [1021-MIRROR-KELLY]", "ratio": 0.98 },
        { "name": "LED_LENGTH@LEDStrip [LED]", "ratio": 0.95 }
      ]
    }
  ]
}
```

Rules files are the most reliable way to handle a known model — they bypass LLM classification entirely and give deterministic results.

## Common Issues

| Symptom | Cause | Fix |
|---|---|---|
| `422 Unprocessable Entity` | Missing required fields in request | Check `dimensions` is not empty |
| LLM returns non-JSON | Model hallucinated prose | `_strip_fences()` in interpret.py handles markdown; add better error logging |
| Wrong components included | Scope misidentified as OVERALL | Check assembly_context has COMPONENT RELATIONSHIP MAP; user should name the component |
| Rules not loading | File name mismatch | Model stem must exactly match rules filename (case-sensitive on Linux) |
| 120s timeout | LLM too slow or unreachable | Check API key, try switching provider in `.env` |
